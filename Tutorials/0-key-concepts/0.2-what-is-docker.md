# What are Docker Containers? 

Docker containers are essentially lightweight Virtual Machines — a small operating system that exists and runs in a partitioned section of your computer. Docker containers can be run from MacOS, Linux and Windows, making them very convenient for creation of a universal experience across operating systems. 

While they can be intimidating to begin with, they are highly popular due to the simplicity of their use. A lot of modern software is packaged and distributed as docker containers to make it easier to deploy, without having to worry about install location and paths. 

## Containers vs Images 
- An image is a saved container which can be packaged and downloaded from an online registry
- A container is an active mini virtual machine 

## Dockerfile

A docker file is a series of commands used to build a container from an existing image. It will generally start with `FROM <registry>/<image>:<tag>` (if no registry is provided, it defaults to docker hub) where the image can be basic and lightweight (e.g. `alpine:latest` for a 5MB operating system) or a bulkier application (e.g. `intersystems/iris-community:latest-em`)

A dockerfile is essentially a template for reliably customizing an existing image. 

## docker compose 

docker compose allows orchestration between different containers. It can be used to add shared volumes between multiple containers or share local directories with containers. 

## Key Commands 


Build a docker compose project
```
docker compose build 
```

Run a docker compose project: 

```
docker compose up -d 
```

Stop a docker compose project

```
docker compose stop 
```

Stop and remove a docker compose project: 

```
docker compose down -v 
```
